Failure inventory, recorded before release integration changes:

- Ordinary browser CI silently skips the opt-in column-audit specs. The release
  gate must invoke the test-only real router/store/worker harness, with a
  representative completion/reopen/stale/retry journey and retained artifacts.
- Running those specs against the production executable would omit fixture
  controls. Keep the harness separate and reuse the already built frontend.
- Retrieval can select incidental audit prose, mistake tests for implementation,
  miss ordinary-English source owners, or turn missing evidence into reopening.
  Actual GitHub and the configured evidence-only model must be tested separately
  from the scripted integration harness before promotion.
- A read/run agent grant is not human Apply authorization. Current beta uses
  Tailnet human assertions; an isolated disabled-auth synthetic human is only an
  integration check. Neither a forged assertion nor a raw session is acceptable.
- Schema 42 can appear compatible under retained SQL while an actual retained
  release executable fails readiness or loses subsequent writes. Exercise each
  actual retained release on a populated upgraded copy; rollback changes images,
  never restores an older database.
- A snapshot or copied account can accidentally target live storage, expose
  private content, or race credential refresh. Use private independent paths,
  check credential lifetime before inference, keep secrets on the app VM, and
  emit aggregate receipts only. Preserve both historical live audit attempts.
- A goal immediately followed by an acceptance heading can swallow that heading
  as goal continuation, dropping every acceptance condition. A populated capture
  must preserve both labeled sections with or without a blank separator before
  evaluation; multiline condition text and exact source lines must remain intact.
