# Separate audit model: failure inventory

Written before the profile implementation and its isolation checks.

- An audit silently uses the everyday drafting model or ignores its own override.
- Changing the audit profile also changes ordinary Luna task or project assistance.
- Empty programmatic configuration falls back to the old lightweight model.
- Malformed model names or unsupported effort values survive startup validation.
- Canonical and compatibility environment aliases disagree without an error.
- A client or scoped agent can choose an arbitrary model or reasoning effort.
- A configuration change rewrites an existing job or changes an idempotent replay.
- Retrieval and final judgment use different profiles instead of the captured job.
- A stronger model produces an expected destination with incorrect citations.
- A probe changes the live database, resets candidate history, or leaves credentials.

Verification: configuration checks establish independent defaults, overrides,
validation, and aliases. The HTTP/store/worker journey establishes server-only
selection, durable capture, replay, and actual runner arguments. Existing semantic
stage checks establish use of the captured job profile. These scripted checks do
not prove model accuracy. Compare the unchanged ordinary-language reference and
negative counterexample against the same pinned source using a real model, review
the citations, retain every attempt, and verify cleanup before promotion.
