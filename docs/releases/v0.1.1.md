# Helm v0.1.1

Helm v0.1.1 is a stability and bug-fix release for task editing, bounded Luna
requests, and private run diagnostics.

## Fixes

- **Task-save races:** Task drawer saves capture the task and the complete
  submitted snapshot before asynchronous label work. Delayed PATCH or label
  responses cannot attach to another task or overwrite edits made after a
  save, navigation, or drawer reopen. Dirty and saved state stays accurate.
- **Bulk selection across filters:** Selected tasks retain their last loaded
  versions during filtered board reloads. Review includes every selected task,
  even while replacement pages are loading or a filter hides part of the selection.
- **Bounded Luna account checks:** Task drafting and project analysis now start
  their feature deadline before calling Codex `account/read`, with a 20-second
  account deadline. A stalled Codex process returns the route's structured
  `503` response while Helm remains ready to serve requests.
- **Concurrent Luna details:** Concurrent run-detail responses merge into the
  latest cache, so an already loaded private input/output detail remains
  visible when another response arrives.
- **Private Luna details:** Run history is actor-scoped. The actor who started
  a run can inspect its stored prompt/input and model output; other actors
  cannot. The history summary stores bounded metadata only; that metadata
  excludes prompts, model output, credentials, and account metadata.
- **Agent mutation limits:** Agent mutations use actor-keyed burst protection
  without a lifetime allowance.
- **Dependency maintenance:** Updated the development serializer dependency;
  the npm dependency audit reports no known vulnerabilities.

## Regression coverage

Board pagination and live reconciliation checks now synchronize in-flight
polling with external-delete refreshes, keeping the browser proof deterministic
for bounded pages and race timing. Project analysis and private Luna run
diagnostics remain available in the roadmap and Settings views. Polling coverage
waits for authoritative refreshes and verifies that unsaved drawer drafts stay intact.

## Database compatibility

Compared with the previous main deployment, v0.1.1 adds no database migration. Upgrading from
v0.1.0 applies additive Luna-history migrations 026, 027, and 028 for runs,
steps, and private content.

## Verification

The validation artifact records 75 distinct workflows: 72 normal workflows,
one local-onboarding workflow, and two stalled-account fault scenarios. The
local-onboarding path was run in both suites. Results had zero unexpected or flaky outcomes,
with no data races reported. Recorded checks cover Svelte checks, OpenAPI
validation, `go vet`, actionlint, formatting and diff checks, the race
detector, and artifact checksums.
